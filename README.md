## Мета

Розробити консольну програму, яка без використання класів розбирає,
перевіряє та агрегує відомості про книги домашньої бібліотеки. Одна книга
містить автора, назву, рік видання, кількість сторінок, жанр і дату прочитання.

## Структура

- `bin/home_library_lab1.dart` — мінімальна точка входу.
- `lib/home_library_lab1.dart` — логіка застосунку, яку можна повторно
  використовувати та аналізувати окремо від запуску програми.
- `docs/` — матеріали звіту та фінальний звіт лабораторної роботи.

Поділ між `bin/` і `lib/` обрано замість розміщення всього коду в одному
файлі. Така структура відокремлює запуск програми від предметної логіки та
спрощує її подальше тестування й перероблення в наступних лабораторних роботах.

## Типи даних

Книга представлена іменованим записом Dart, а результат розбору — окремим
записом із nullable-полями для книги та опису помилки. Список коректних
записів зберігається у `List`, а групування за жанром буде виконано через
`Map<String, List<...>>`. Класи не використовуються відповідно до умови
лабораторної роботи.

Валідатор повертає `List<String>` з усіма порушеннями: перевіряє рік видання,
кількість сторінок, формат імені автора та послідовність дат. Формат автора
перевіряється регулярним виразом з іменованими групами; той самий вираз
використовується для маскування частини імені через `replaceAllMapped`.
Кількість днів після прочитання обчислюється методом `DateTime.difference`.

Альтернативою був `Map<String, Object?>` для кожної книги, однак іменований
запис дає статичну перевірку типів і унеможливлює помилки в назвах полів.

## Залежності

Застосунок не має сторонніх залежностей часу виконання. Пакет `lints`
підключено лише як залежність розробки для набору правил статичного аналізу
`recommended`. Альтернативою було вручну підтримувати перелік правил у
`analysis_options.yaml`, але стандартний набір простіше перевіряти та
оновлювати.

Пакети `path`, `collection` і `intl` не використовуються: для лабораторної
роботи достатньо стандартної бібліотеки Dart.

## Null safety

Оператори `!`, ключове слово `late` і тип `dynamic` у проєкті не
використовуються.

